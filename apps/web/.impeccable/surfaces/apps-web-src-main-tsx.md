# Guided reliability demonstration

## Scope and visitor mode

Operate / Read. Replace the single-page form/ledger layout with an accompanied
scenario demonstration and a separate technical-controls tab. Existing business
contract and browser intention remain durable. No invented database outcomes.

## Direction contract

THESIS: A presenter advances through a request's real journey, one useful action at
a time. The two simultaneous truths, client confirmation and server persistence,
are the central teaching instrument instead of a wall of identifiers.

OWN-WORLD: A rehearsal cue sheet expressed as a precise browser workspace: deep
navy ink, cool near-white stage, cobalt for the next action, muted violet for unknown
confirmation and green for recorded facts. Sans-serif task typography, two purposeful
comparison panels, compact horizontal lesson navigation, explicit tab controls.

STORY: Start with a familiar repeated-send problem. Send the fictional request,
observe the missing confirmation beside the actual saved record, retry, and explain
why the same record returns. Move to concurrent sends, rollback, conflict and a
separate new request. Technical details are a deliberate second reading.

FIRST VIEWPORT: Header and two tabs; a compact lesson strip; current situation and
one next-action button on the left; a wide shared observation stage on the right,
client above one half and server above the other. The stage changes with actual HTTP
and refreshed records. An outcome sentence explains the next step after each send.
Mobile places the situation and action before the two stacked observations.

FORM: Rehearsal cue sheet, candidate 7, seed 06b2ce27; selected by the user as an
accompanied, one-step-at-a-time demonstration. Grounded candidates: tabletop workshop,
science exhibit, service ticket, storyboard, troubleshooting map, annotated notebook,
rehearsal cue sheet. The user chose code-first construction. Declined catalog forms
(barcode field, dense catalog, cassette, factory sleeve, star atlas) lose novice clarity;
retain contrast, state traceability, explicit step boundaries, restraint and focus.
Airport signage is competitive on next-action clarity; retain one decision per scene.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## Confirmation and boundaries

User confirmed accompanied use, direct code construction and the one-step demonstration.
No generated raster assets needed; runtime observations supply the central geometry.
This contract is development-only and never imported into browser output.
