# Scenario workspace C

## Scope and visitor mode

Operate / Read. User approved C and its integrated technical-panel revision on
2026-10-15. One page per scenario. No top-level demo/technical tabs. The technical
panel starts collapsed and closes when navigating to another scenario.

## Direction contract

THESIS: One request, two observations, one next action. A presenter shows what the
client knows beside what the server actually saved, then retries to resolve uncertainty.

OWN-WORLD: A quiet scenario workspace with a cool near-white rail, navy text, cobalt
primary action, violet uncertainty and green observed persistence. Six numbered
scenarios at the left; a direct request/reply exchange at the center. Preserve the
locally served Atkinson typeface and durable HTTP behavior from the previous version.

STORY: Send twice, lose a reply, send together, fail before saving, change content,
and create another. Every scenario offers its next action. Explanation is disclosed
on demand. Technical evidence belongs to the same workspace and current scenario.

FIRST VIEWPORT: Scenario rail, thin position/status bar, short title and one sentence.
Client/server icons face each other across request/reply arrows. Two observed counts
and a primary action sit above the bottom technical disclosure. Expanded evidence
reflows below the action. On narrow screens a native scenario selector replaces the
rail; the same exchange remains visible and the technical columns stack.

FORM: Scenario workspace C, exploration seed 1e147a4b, candidate 3, chosen by the
user. Approved reference: .impeccable/mocks/dashboard-v3/c-integrated-technical-panel.png.
The image shows the drawer expanded for review; runtime default is collapsed.
Its illustrative IDs and dates are replaced by actual records. The lost POST cannot
confirm an ID: the separate GET evidence can observe it. Manual next-attempt settings
sit in Advanced tools, so they cannot appear to control the guided action.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## Constraints

No fake backend logs, no invented outcomes, no destructive resets on navigation.
One active intention is retained across refresh and scenario browsing. Starting another
scenario explicitly replaces that intention while retaining previous database rows.
The main action stays above the panel in normal flow. No fixed overlay or fake resize grip.

## Refinement accepted 15 October 2026

The user requested manual scenario changes through the navigation only, an in-place
restart action after completion, the introduction below each scenario title, removal
of the top-right mode label, and clearer screen/server exchange animations. Preserve
the C visual world and collapsed technical panel. Motion illustrates actual sends and
observed replies without claiming measured network timing; reduced motion is static.
